مرجع تفصيلي للمطورين لبيئة عمل ومشروع Calltranslate

1. المعمارية العامة ومكونات النظام (System Overview)

نظام Calltranslate هو منصة متكاملة للاتصال الصوتي والمحادثات المترجمة فورياً بنمط تطبيق Telegram، مبنية على التقنيات التالية:

  • Backend Framework: Python 3.12+ مع FastAPI و Uvicorn و WebSockets غير المتزامنة.
  • Database: SQLite3 مع تفعيل نمط WAL (Write-Ahead Logging) وربط المفاتيح الخارجية PRAGMA foreign_keys=ON;.
  • WebRTC Media: اتصال صوتي مباشر Peer-to-Peer بين طرفي المكالمة لنقل الصوت بأدنى زمن تأخير (Ultra-low latency).
  • AI Translation Engine: دعم ثنائي لموديل Google Gemini Multimodal Live API (عبر Bidi WebSocket) و OpenAI Realtime API. الموديل الافتراضي هو Gemini 3.5 Live (gemini-3.5-live-translate-preview).
  • Signaling & Presence Hub: فئة UserHub للتعامل مع وجود المستخدمين (Online/Offline)، إرسال إشعارات طلبات الصداقة المباشرة، وإشارات رنين المكالمات.

2. هيكل وتصميم قاعدة البيانات (Database Schema)

يتم تخزين جميع البيانات بملف واحد دائم calltranslate.db. الجداول الأساسية:

اسم الجدولالوظيفةالحقول الأساسية
users حسابات المستخدمين والصلاحيات id, username, password_hash, salt, display_name, language, assigned_model, is_admin, created_at, last_seen
contacts قوائم الأصدقاء وجهات الاتصال id, user_id, contact_user_id, created_at
friend_requests طلبات الصداقة الصادرة والواردة id, from_user_id, to_user_id, created_at
messages المحادثات الكتابية والترجمة الفورية id, from_user_id, to_user_id, original_text, translated_text, from_lang, to_lang, created_at
sessions جلسات تسجيل الدخول وتوكنات Bearer token, user_id, created_at, expires_at

حماية وتشفير كلمات المرور:

تستخدم الدالة db.hash_password() خوارزمية PBKDF2-HMAC-SHA256 بـ 100,000 تكرار مع ملح عشوائي 16-byte فريد لكل مستخدم.

ملاحظة للمطور: تم عزل بيئة الاختبارات (Pytest) بحيث تستخدم مسار قاعدة بيانات مؤقت في /tmp عبر متغير البيئة CALLTRANSLATE_DB_PATH، لضمان عدم حذف أو تصفير بيانات الإنتاج نهائياً عند تنفيذ الفحوصات البرمجية.

3. دورة حياة المكالمة والترجمة الصوتية (Audio & Call Flow)

  1. إرسال إشارة الاتصال (Call Signaling): يقوم المستخدم أ بإرسال {"type": "call_user", "target": "bob"} عبر /ws/user-hub. يتحقق السيرفر من وجود المستخدم وحالته (Online)، ثم ينشئ غرفة مؤقتة برمز فريد عبر room_store.issue_fixed_access(room_id, role) لكل طرف.
  2. رنين وقبول المكالمة: يستلم المستخدم ب حدث incoming_call مع إشارة صوتية ونافذة رنين. عند الضغط على قبول (Accept)، يرسل accept_call.
  3. إنشاء مسار WebRTC (P2P): يتصل الطرفان بمقبس الإشارات /ws/{room_id}/{role} ببروتوكول calltranslate وتوكن الدخول ct_...، ويتبادلان عروض SDP Offer / Answer ومرشحات ICE Candidates.
  4. التقاط الصوت وعلاج مشكلة متصفحات كروميوم (Chromium RTP Puller): متصفحات كروميوم تتجاهل فك تشفير مسار WebRTC الصوتي ما لم يتم ربطه بعنصر وسائط نشط. يتم ربط المسار الصوتي فورياً بـ: 
    <audio id="appAudioPuller" muted playsinline hidden></audio>
    ثم سحبه إلى AudioContext.createMediaStreamSource(stream).
  5. معالجة وبث الصوت للذكاء الاصطناعي (Gemini Live interpretation): يتم تخفيض معدل العينات (Downsampling) من عينة المتصفح إلى 16,000 Hz 16-bit Mono PCM وبثها بصيغة Base64 كقطع realtimeInput عبر WebSocket إلى GenerativeService.BidiGenerateContent.
  6. تشغيل الترجمة الصوتية: يعيد النموذج دفقات صوتية PCM بمعدل 24,000 Hz، يتم تحويلها إلى Float32 وتشغيلها بتسلسل زمني سلس عبر AudioContext.createBufferSource() في أذن الطرف الآخر.

4. المحادثة الكتابية والترجمة المباشرة (Chat & Translation)

  • واجهة المحادثة: عند الضغط على أي جهة اتصال، تفتح شاشة المحادثة المباشرة بنمط فقاعات التيليجرام.
  • الترجمة التلقائية: يتم إرسال النص إلى POST /api/messages/{username}، حيث تقوم الدالة translate_text() بترجمة النص تلقائياً عبر نموذج Gemini إلى لغة المستلم.
  • عرض الرسائل: تظهر كل فقاعة محادثة النص الأصلي وتحته سطر الترجمة الفورية بلون هادئ مع وقت الإرسال.
  • التوصيل اللحظي: يتم تسليم الرسالة المنشورة عبر user_hub.send_to_user() في نفس اللحظة عبر الـ WebSocket للمستلم دون الحاجة لتحديث الصفحة.

5. نظام الصداقات والبروفايل (Friend Requests & Contacts)

  • الطلبات الصادرة (Outgoing Requests): عند إرسال طلب صداقة، يظهر فوراً في شاشة المرسل تحت "طلبات الصداقة الصادرة (بانتظار الموافقة)" مع إمكانية إلغاء الطلب.
  • الطلبات الواردة (Incoming Requests): تظهر للمستلم لحظياً عبر الـ WebSocket تحت "طلبات الصداقة الواردة" مع زري قبول ورفض.
  • حذف الصديق (Delete Contact): زر الحذف موجود حصرياً داخل شاشة المحادثة / البروفايل الخاصة بالمستخدم (وليس في القائمة الرئيسية) للحفاظ على تجربة استخدام نظيفة وبسيطة.

6. تشغيل السيرفر والإدارة (Deployment & Administration)

إدارة الخدمة على السيرفر (Systemd Service):

# مسار ملف الخدمة
/etc/systemd/system/calltranslate.service

# أوامر التحكم الأساسية
sudo systemctl restart calltranslate
sudo systemctl status calltranslate
sudo journalctl -u calltranslate -n 50 -f

صلاحيات قاعدة البيانات:

يجب أن تملك خدمة calltranslate صلاحية الكتابة للمجلد /srv/calltranslate عبر تفعيل ReadWritePaths=/srv/calltranslate وضبط الصلاحيات:

sudo chown -R calltranslate:calltranslate /srv/calltranslate/calltranslate.db*
sudo chmod 664 /srv/calltranslate/calltranslate.db*

لوحة الإدارة (Admin Panel):

تتيح لوحة الإدارة في /admin للمسؤول التحكم بنموذج الترجمة المخصص لكل مستخدم على حدة من بين:

  • gemini-3.5-live-translate-preview (الافتراضي - الأحدث والأعلى دقة)
  • gemini-2.5-flash-native-audio-latest
  • openai-realtime
